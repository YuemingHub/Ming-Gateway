===== resource footprint (same host, same mock, same load) =====
Date: 2026-09-26 (Asia/Shanghai)
Host: Windows 11, 16 logical CPUs visible to the Go runtime; small-host class target per Ming-Gateway README (1C2G).

Method:
  - Bifrost: powershell Get-Process on bifrost-http (Go binary, v2.2.3)
  - Ming-Gateway: node gateway.js, located by CommandLine match (scripts/measure-gateway.ps1)
  - Load: node scripts/loadgen.mjs --n 200 --c 10 (200 requests, concurrency 10, non-stream)

  load result:       ok=200 err=0   p50=10 ms  p95=31 ms   wall=251 ms

Bifrost startup time: ~7-12 s to first healthy response (binary bootstrap measured 6.8 s in logs).
Ming-Gateway startup time: < 2 s.

Ming-Gateway README's own documented footprint: "内存占用约 40–60MB，1.6G 的小机器完全够用".
Observed multiplier on the same host: Bifrost ≈ 3.6–4.8x Ming-Gateway RSS.

Notes:
  - Bifrost's RSS includes the embedded web UI, sqlite config/log stores and the Go runtime arena; it fell back after load (GC), so ~240 MB is the steady state after warm-up.
  - config.db reached 29 MB after this pilot session (config + content logs while content logging was on).
